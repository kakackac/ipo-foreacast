# 상장 직전 전향적 검증 운영

## 현재 상태와 범위

2026-09-16 연구용 예측 기록 및 공식 가격 평가 CLI를 추가했다. 서비스 출시 보류는 유지한다. 기존 2026년 최종 평가를 반복하거나 모델 설정을 바꾸지 않는다. 기존 저장소의 예측 upsert는 과거 기록을 덮어쓰므로 연구용 SQLite 원장을 별도로 사용한다.

실제 로컬 features_all.parquet의 2026-09-16 이후 상장 예정 행은 0건이다. 따라서 실종목 예측은 발행하지 않았다. 합성 테스트는 기능 검증일 뿐 모델 성능 근거가 아니다.

## 구현된 처리

1. predict: 고정 실험 manifest와 개발 데이터 해시를 검사하고 기존 개발 데이터만으로 동일 모델을 학습한다. 2026년 holdout은 열지 않는다. 시초가 트리 모델과 평균·중앙값 기준선, 종가 평균·중앙값 기준선을 기록한다.
2. 입력: 일반 IPO 및 KOSPI/KOSDAQ만 허용한다. 피처 목록은 실험 계약과 정확히 일치해야 한다. 기관 경쟁률·통합 확약은 필수이며 확약 단위는 0~1이다. 개인청약은 계약에 없고 사용하지 않는다.
3. 시점: 실제 시스템 시각으로 상장 전날 21:00~23:59 KST에만 기록한다. CLI에 과거 시각 지정 옵션은 없다. 원천 공개시각 <= 수집시각 <= 입력 기준시각을 검사하며 모든 시각에 시간대가 필요하다.
4. 근거: 값과 감사 원시값 일치, 검증 상태, 사람 검토 불필요를 확인한다. 입력 출처는 DART/KRX/공식 주관사/공식 데이터 파생값에 한정한다. 임의 URL이나 인증 헤더 대신 공개 문서 식별자를 저장한다. 결측은 허용된 사유와 함께 NULL로 유지하고 학습 구간 중앙값으로만 전처리한다.
5. 원장: event_id별 한 번만 INSERT한다. 예측의 UPDATE/DELETE와 중복 입력은 차단한다. 입력·근거·시각·모델 설정·학습 해시·예측을 함께 보관하며 SHA-256으로 읽기 시 변조를 확인한다.
6. resolve: 상장 당일 21:00 KST 이후에 해당 이벤트·날짜의 검증된 KRX 정규장 시가/종가만 연결한다. 시간외 가격을 종가 타깃으로 사용하지 않는다. 확정 공모가 대비 수익률과 방법별 절대오차를 예측과 별도 테이블에 기록한다.

## 실행 인터페이스

저장소 루트에서 실행한다. 아래 입력 파일은 **신규 공식 수집기의 검증 산출물**이어야 한다. 사람이 검증 상태 문자열만 임의로 붙인 파일은 공식 검증 완료가 아니다.

```bash
python ipo_predictor/scripts/prospective_listing_eve.py status \
  --database ipo_predictor/data/processed/prospective/listing_eve.sqlite

python ipo_predictor/scripts/prospective_listing_eve.py predict \
  --database ipo_predictor/data/processed/prospective/listing_eve.sqlite \
  --experiment ipo_predictor/data/processed/experiments/listing_eve_v1/636eae2880f279a3 \
  --input <검증된_상장예정_입력.json>

python ipo_predictor/scripts/prospective_listing_eve.py resolve \
  --database ipo_predictor/data/processed/prospective/listing_eve.sqlite \
  --input <검증된_KRX_상장일_가격.json>
```

predict 입력은 event_id, listing_date(YYYY-MM-DD), offering_type=general_ipo, market, offering_price, offering_price_evidence, features, evidence를 포함한다. evidence는 피처별 raw_value, source, source_reference, available_at, collected_at, verification_status=verified, human_review_required=false를 포함한다. 가격 근거에도 동일 필드가 필요하다. 결측 피처 근거에는 missing_reason을 남긴다.

resolve 입력은 event_id, price_date, session=KRX_REGULAR, open_price, close_price, evidence를 포함한다. evidence에도 해당 event_id, price_date, open_price, close_price가 있어야 하며 출처는 KRX다. 원문 근거를 이 인터페이스에 연결하는 수집 어댑터는 아직 구현되지 않았다.

## 남은 실제 운영 연결

- 현재 파이프라인은 과거 상장 결과 기반이다. 상장 예정 이벤트의 공식 일정과 상장 전 피처를 수집하는 어댑터가 필요하다. 과거 features_all을 재실행하는 것으로 이 기능을 대체할 수 없다.
- 기존 관측 원장의 검증 상태를 단순히 verified로 이름만 바꿔서는 안 된다. 신규 어댑터는 원문·규칙·이벤트 연결·공개시각을 검증해 입력 계약으로 변환해야 한다. 현 CLI는 신뢰된 내부 입력용이며 외부 사용자 입력 API가 아니다.
- 21시 작업의 자동 스케줄 등록, 재시도·누락 경보, 상장 일정 변경/취소 처리, 공식 정정 가격의 추가 버전 처리, 원장 백업은 아직 연결하지 않았다. 실패 입력은 원장을 수정하지 않고 오류를 반환한다. 정정이 필요하다고 기존 기록을 삭제해서는 안 된다.
- SQLite 트리거는 애플리케이션 실수에 대한 보호이며 관리자 파일 조작까지 막는 WORM 저장소가 아니다. 해시도 외부 서명/타임스탬프를 대체하지 않는다.
- 테스트가 통과해도 실제 예측 성능이 입증된 것은 아니다. 이후 신규 표본에서 사전 정의한 평가 기간·표본 기준을 별도로 고정해야 하며, 중간 결과를 보고 반복 조정하지 않는다.

이번 완료 범위는 기록·평가 코드 경로와 테스트다. 자동 수집부터 일정 실행까지 모두 가동됐거나 앱 출시가 완료됐다고 주장하지 않는다.
