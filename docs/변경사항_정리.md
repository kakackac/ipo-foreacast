# 공모주 상장일 수익률 예측 서비스 변경사항 정리

이 문서는 이 프로젝트의 기능 추가, 데이터 품질 개선, 큰 오류 수정과 검증 결과를 계속 기록하는 기준 문서다. 새로운 항목은 아래에 추가하며, 각 항목에는 변경 이유, 사용자·데이터 영향, 검증 방법과 남은 확인 사항을 함께 남긴다.

## 서비스 기준

- 목적: 상장 전에 공개된 공시·수요예측·재무 정보를 바탕으로 상장일 시초가와 종가 수익률을 각각 예측한다. 투자 권유 기능은 제공하지 않는다.
- 시초가 수익률: `(상장일 09:00 시초가 / 확정 공모가 - 1) x 100`
- 종가 수익률: `(상장일 종가 / 확정 공모가 - 1) x 100`
- 상장 후 실제값 반영: 상장일 21:00 KST에 상장일 시가·종가를 확정 저장한다.
- 주요 원천: OpenDART(신고서, 수요예측, 재무제표), KRX OpenAPI(상장 일정, 상장일 가격, KOSPI/KOSDAQ 지수).

## 현재 상태 요약 (2026-08-27)

- KRX KIND 공식 신규상장 이벤트 마스터는 2015-01-15부터 2026-08-25까지 1,512건을 저장했다. 일반 IPO 985건, 스팩 IPO 324건, 재상장 74건, 분류 불명/검토 85건 등을 별도 분류했다.
- 이전 `LIST_DD` 후보 1,318건은 삭제하지 않고 `legacy_list_dd_candidate.parquet`로 보존했다. 공식 이벤트와의 비교는 일치 1,219건, 공식 원천만 293건, 레거시만 99건이다.
- 기존 DART·가격·피처 산출물은 아직 새 공식 이벤트 마스터 전체로 재수집하지 않았다. 따라서 기존의 46개 타깃과 새 일반 IPO 모집단 985건을 결합해 학습 가능 표본이라고 해석하면 안 된다.
- 실제 DART/KRX 인증 키가 이 작업 환경에는 설정돼 있지 않아, 275건 DART 014 접수번호의 온라인 재감사와 상장일 가격·KRX 표준코드 보강은 실행하지 않았다. 키가 있는 수집 환경에서만 수행한다.
- 모델 성능 수치는 보고하지 않는다. 학습·백테스트 명령은 일반 IPO, 검증 공모가, 상장 전 정보 검증, 최소 표본·피처 충족률을 모두 통과하지 않으면 중단한다.

## 변경 이력

### 2026-08-27 - 수요예측 DART 014 재시도 캐시 및 Pandas 경고 수정

- 문제: 일부 과거 수요예측 접수번호는 DART 원문 ZIP이 없어 `014`를 반환한다. 이 실패가 공모가 수집 전체를 중단시키지는 않지만, 매 실행마다 같은 원문을 다시 요청하고 경고를 반복했다. 또한 기존 014 이력의 `retriable` 결측 보정에서 Pandas 향후 동작 경고가 발생했다.
- 변경: 수요예측 원문 실패를 `dart_demand_document_failures.parquet`에 접수번호 단위로 기록하고, 7일 안에는 재요청하지 않는다. 이후에는 다시 시도하므로 영구 제외하지 않는다. `retriable` 열은 명시적 불리언 변환으로 정규화했다.
- 영향: `014` 수요예측은 해당 종목의 기관 경쟁률·확약만 결측으로 남으며, 상장 이벤트·공모가·시초가·종가 수집은 계속 완료된다. 동일 오류 로그는 다음 실행에서 크게 줄어든다.
- 검증: 같은 수요예측 접수번호가 첫 실행에서 한 번만 호출되고, 두 번째 실행에서는 재시도 보류되는 회귀 테스트를 추가했다.

### 2026-08-27 - 공식 KRX 이벤트 마스터·DART 계보·학습 안전장치 전환

- 문제: `LIST_DD` 1,318건은 현재 종목기본정보 스냅샷이라 IPO 공식 모집단이 아니고, 46개 확정 타깃 중 스팩이 다수여서 일반 IPO 모델의 근거가 될 수 없었다. DART 014도 잘못 선택된 접수번호 하나가 실패하면 회사 전체를 영구 제외하는 구조였다.
- 변경:
  - KRX KIND `신규상장기업현황`을 이벤트 마스터 원천으로 교체하고, 종목코드·표준코드·회사명·시장·상장일·증권구분·주식종류·상장유형·공모가·공모주식수·주관사·분류 근거·원천·수집시각·검증 상태를 보존한다. KIND에 없는 표준코드·시장·업종코드는 KRX OpenAPI 가격 조회 시 보강하도록 상태를 분리했다.
  - 일반 IPO, 스팩 IPO, 이전상장 검토, 재상장, 외국기업, 우선/종류주, 리츠·ETF·ETN·펀드 비대상, 분류 불명을 명시적으로 분류한다. KIND가 이전 시장을 주지 않는 이전상장은 추측하지 않고 검토 대기 상태로 둔다.
  - `collection_manifests/`와 `latest_collection_manifest.json`을 추가해 요청 연도, 응답 건수, 캐시 사용, 실패 내용, 종료 상태를 기록한다. `collect-events`는 DART·가격 API 없이 공식 이벤트 마스터만 갱신하며 `--refresh-events`로 전체 원천을 다시 조회할 수 있다.
  - DART는 회사명으로 후보를 찾더라도 단일 DART 고유번호가 확인된 경우에만 접수번호 계보를 만든다. 복수 고유번호면 자동 연결하지 않는다. 동일 회사의 최초·정정·발행조건확정 후보를 모두 계보 파일에 저장하고, 014면 다음 후보를 계속 탐색한다.
  - 014 실패는 접수번호 단위 이력으로 누적하고 7일 재시도 정책과 대체 후보 정책을 분리했다. `audit-dart-failures`는 키가 있는 환경에서 기존 실패 접수번호를 다시 감사한다.
  - 희망 밴드, 확약, 신주·구주, 유통물량, 시장 모멘텀의 미수집 값을 0·0.5로 만들지 않는다. 피처 원시값과 결측 여부·사유·출처·원천 참조·수집 시각·검증 상태·사람 검토 필요 여부는 `feature_observations.parquet`에 별도 저장한다.
  - `SECT_TP_NM`은 산업이 아니라 `listing_segment`로만 취급한다. 산업명은 KIND의 별도 업종 열을 사용하며, 업종코드가 없으면 결측·보강 대기로 남긴다. 개인 청약 경쟁률은 주관사 공식 공지를 수집하기 전까지 결측으로 유지한다.
  - 같은 상장일은 제외한 과거 행만으로 최근 IPO 온도와 섹터 PER 기준을 계산한다. 피처 공개시각이 상장일 뒤이면 `feature_time_validation.parquet`에서 차단한다. 결측 보정은 각 백테스트 윈도의 순수 훈련 구간에서만 계산한다.
  - OpenDART 재무 단일계정 API는 사업연도만 주고 실제 공시 접수시각을 주지 않으므로, 재무 공시 계보를 추가하기 전에는 재무 수치를 모델 피처에서 제외한다. 원시 재무값은 감사용 파일에만 보존한다.
  - 실제 학습·백테스트는 일반 IPO만 대상으로 하며, 검증 공모가, 시초가·종가 타깃 100건 이상, 연도 분포, 핵심 피처 평균 충족률 70% 이상, 미래 정보 위반 0건이 충족될 때까지 중단한다.
- 실제 원천 검증:
  - 2026-01-01~2026-08-27 KIND 요청 성공: 41건 저장. 일반 IPO 29, 스팩 9, 재상장 2, 외국기업 1.
  - 2015~2026 강제 재수집 성공: 1,512건. 일반 IPO 985, 스팩 324, 분류 불명 85, 재상장 74, 비대상 23, 외국기업 18, 우선/종류주 3.
  - 공식 이벤트의 주관사 결측은 1건이다. 공모가 결측은 318건이며 값이 없는 그대로 보존한다.
- 영향: 지금은 기존 피처의 성능을 비교할 단계가 아니다. 전체 DART 계보·공모가·상장일 가격을 새 이벤트 마스터 기준으로 재수집한 뒤에만 일반 IPO 학습 가능 행 수를 계산한다.
- 검증: 문법 검사 및 KRX·DART·피처 회귀 단위 테스트 34개 통과. 014 대체 접수번호 탐색, 결측 보존, 미래 정보 차단, 46건 표본 학습 차단을 자동 테스트했다. 학습·백테스트·성능 산출은 실행하지 않았다.
- 다음 확인: 키가 설정된 수집 환경에서 `collect --start-year 2015 --end-year 2026 --phase phase2`와 `audit-dart-failures`를 실행해 DART 실패 원인별 건수, 일반 IPO 검증 타깃 수, 피처 충족률과 실제 시간 검증 결과를 이 문서에 추가한다.

### 2026-08-26 - 확정 공모가 직접 연결·표 행 검증

- 문제: 이전 규칙은 확정가 문구 뒤 140자에서 금액을 찾았다. 같은 범위에 액면가·희망 밴드·총공모금액이 있으면 잘못된 금액을 자동 승인할 위험이 있었다.
- 변경:
  - 자동 승인은 확정·최종 공모가 라벨과 `원` 또는 `KRW` 금액이 같은 문장에 직접 이어진 경우만 허용한다.
  - DART HTML/XML의 표 행을 보존해 `확정 공모가` 라벨과 같은 행의 금액 칸도 승인한다.
  - 희망·밴드·액면·총공모·모집총액 문맥과 `~` 범위 표기는 자동 승인에서 제외한다.
  - 파서 규칙 버전을 원시 데이터에 기록한다. 규칙 버전이 바뀌면 기존 문서를 한 번 재파싱하고 이후에는 캐시를 다시 사용한다.
- 영향: 자동 승인 타깃 수는 줄거나 늘 수 있으며, 재수집 결과로만 확정한다. 애매한 값은 삭제하지 않고 감사 대기열에 남는다.
- 검증: 전체 단위 테스트 29개 통과. 같은 문장 승인, 인접 액면가·희망밴드 거부, 같은 표 행 승인을 각각 테스트했다.
- 다음 확인: 재수집 후 `final_price_same_sentence`, `final_price_table_row`, `needs_review_*` 상태별 건수를 기록한다.

### 2026-08-26 - 공모가 예정 문구 오인 방지와 구조화 조회 진단

- 문제: 재수집 감사 결과 452건 중 399건이 `needs_review_no_currency_unit`이었다. 원문을 확인한 결과 다수는 `1주당 확정공모가액을 최종 결정할 예정`이라는 초기 신고서 문구의 `1`을 숫자 후보로 잡은 사례였다. 또한 구조화 공모가 대조 결과가 모두 `not_available`로 남아 실제 검증에 쓰이지 않았다.
- 변경:
  - `결정할 예정`, `정정신고서를 제출할 예정` 문맥은 `preliminary_price_language`로 분리한다. 이때 `1주당`의 `1`은 공모가 후보로 저장하지 않는다.
  - 신고서 제목의 `[발행조건확정]`만으로 확정가라고 판단하지 않고, 원문에서 실제 금액과 확정 문구가 확인될 때만 자동 학습 후보로 인정한다.
  - OpenDART `estkRs`의 검색일은 문서 기준인 최초접수일을 고려해 상장일 전 최대 400일로 넓혔다.
  - 구조화 응답이 없었는지(`source_no_result`), 응답은 있으나 접수번호가 다르는지(`no_matching_receipt`)를 감사 파일에 분리해 남긴다.
- 영향: 기존 46건이 정확히 얼마나 늘어나는지는 다음 재수집 완료 후에만 확정한다. 확정 문구가 없는 초기 신고서는 자동 학습에 포함하지 않는다.
- 검증: 단위 테스트 25개 통과. 예정 문구에서 `1`을 공모가로 오인하지 않는 회귀 테스트를 추가했다.
- 다음 확인: 재수집 후 `structured_price_check` 상태별 건수, `preliminary_price_language` 건수, 시초가·종가 타깃 수를 기록한다.

### 2026-08-26 - 시장 이전 상장의 IPO 중복 연결 방지

- 문제: 최근 수집에서 DART 452건에 피처 행이 453건이었다. 더블유게임즈가 2015년 최초 상장과 2019년 시장 이전 상장에 이름만으로 모두 연결된 것이 원인이었다.
- 변경: DART 공시 행에는 수집 시점에 연결한 KRX 실제 상장일을 저장하고, 피처 병합 시 같은 회사라도 상장일이 다르면 해당 KRX 이벤트를 제외한다.
- 영향: 최초 IPO만 학습 행으로 남고, 시장 이전 상장·후속 상장이 상장일 수익률 타깃을 중복 생성하지 않는다.
- 검증: 전체 단위 테스트 26개 통과. 동일 회사의 두 상장일 중 DART 연결 상장일만 남기는 회귀 테스트를 추가했다.
- 다음 확인: 다음 수집에서 피처 행 수가 DART 정합 행 수와 일치하는지 확인한다.

### 2026-08-26 - 캐시 날짜 형식 오류 수정

- 커밋: `d6d57c7` (`Normalize cached listing dates before parquet writes`)
- 문제: 캐시에서 가져온 `listing_date`는 날짜 객체이고 새 KRX API 응답은 문자열이어서, 두 값이 한 열에 섞이면 Parquet 저장 중 `ArrowTypeError`가 발생했다.
- 변경: 상장일 가격 수집 결과의 `listing_date`를 저장 전에 항상 날짜형으로 정규화했다.
- 영향: 중단된 `collect` 실행을 같은 명령으로 다시 시작할 수 있다. 기존 캐시 파일을 삭제할 필요는 없다.
- 검증: 전체 단위 테스트 24개 통과. 캐시 재실행 후 Parquet의 날짜 열이 날짜형인지 확인하는 회귀 테스트를 추가했다.
