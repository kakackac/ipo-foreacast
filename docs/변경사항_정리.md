# 공모주 상장일 수익률 예측 서비스 변경사항 정리

이 문서는 이 프로젝트의 기능 추가, 데이터 품질 개선, 큰 오류 수정과 검증 결과를 계속 기록하는 기준 문서다. 새로운 항목은 아래에 추가하며, 각 항목에는 변경 이유, 사용자·데이터 영향, 검증 방법과 남은 확인 사항을 함께 남긴다.

## 서비스 기준

- 목적: 상장 전에 공개된 공시·수요예측·재무 정보를 바탕으로 상장일 시초가와 종가 수익률을 각각 예측한다. 투자 권유 기능은 제공하지 않는다.
- 시초가 수익률: `(상장일 09:00 시초가 / 확정 공모가 - 1) x 100`
- 종가 수익률: `(상장일 종가 / 확정 공모가 - 1) x 100`
- 상장 후 실제값 반영: 상장일 21:00 KST에 상장일 시가·종가를 확정 저장한다.
- 주요 원천: OpenDART(신고서, 수요예측, 재무제표), KRX OpenAPI(상장 일정, 상장일 가격, KOSPI/KOSDAQ 지수).

## 현재 상태 요약 (2026-08-26)

- 실제 과거 이력 수집 범위는 2015년부터 실행 시점까지다.
- 최근 수집 실행에서는 KRX 상장 캘린더 1,318건, DART 연결 454건, 피처 행 456건이 생성되었다.
- 이 수치는 아직 학습 데이터 품질이 확정되었다는 뜻이 아니다. KRX 캘린더에는 일반 IPO 외 상장 이벤트가 섞일 수 있으며, DART 연결은 회사명·접수일·상장일 조건을 만족한 항목만 남는다.
- 기존 실행의 시초가·종가 타깃 46건은 원문 숫자 오인을 막기 위해 공모가 검증을 매우 보수적으로 적용한 결과다. 새 구조화 공시 대조를 포함한 재수집 후 상태별 행 수를 다시 확인해야 한다.
- 모델 성능 수치는 아직 보고하지 않는다. 검증 완료 공모가를 가진 충분한 시계열 학습·검증 표본을 만든 뒤에만 백테스트 MAE, RMSE, 방향 정확도와 기간별 성능을 기록한다.

## 변경 이력

### 2026-08-26 - 공모가 예정 문구 오인 방지와 구조화 조회 진단

- 문제: 재수집 감사 결과 452건 중 399건이 `needs_review_no_currency_unit`이었다. 원문을 확인한 결과 다수는 `1주당 확정공모가액을 최종 결정할 예정`이라는 초기 신고서 문구의 `1`을 숫자 후보로 잡은 사례였다. 또한 구조화 공모가 대조 결과가 모두 `not_available`로 남아 실제 검증에 쓰이지 않았다.
- 변경:
  - `결정할 예정`, `정정신고서를 제출할 예정` 문맥은 `preliminary_price_language`로 분리한다. 이때 `1주당`의 `1`은 공모가 후보로 저장하지 않는다.
  - 신고서 제목의 `[발행조건확정]`만으로 확정가라고 판단하지 않고, 원문에서 실제 금액과 확정 문구가 확인될 때만 자동 학습 후보로 인정한다.
  - OpenDART `estkRs`의 검색일은 문서 기준인 최초접수일을 고려해 상장일 전 최대 400일로 넓혔다.
  - 구조화 응답이 없었는지(`source_no_result`), 응답은 있으나 접수번호가 다르는지(`no_matching_receipt`)를 감사 파일에 분리해 남긴다.
- 영향: 기존 46건이 정확히 얼마나 늘어나는지는 다음 재수집 완료 후에만 확정한다. 확정 문구가 없는 초기 신고서는 자동 학습에 포함하지 않는다.
- 검증: 단위 테스트 25개 통과. 예정 문구에서 `1`을 공모가로 오인하지 않는 회귀 테스트를 추가했다.
- 다음 확인: 재수집 후 `structured_price_check` 상태별 건수, `preliminary_price_language` 건수, 시초가·종가 타깃 수를 기록한다.

### 2026-08-26 - 캐시 날짜 형식 오류 수정

- 커밋: `d6d57c7` (`Normalize cached listing dates before parquet writes`)
- 문제: 캐시에서 가져온 `listing_date`는 날짜 객체이고 새 KRX API 응답은 문자열이어서, 두 값이 한 열에 섞이면 Parquet 저장 중 `ArrowTypeError`가 발생했다.
- 변경: 상장일 가격 수집 결과의 `listing_date`를 저장 전에 항상 날짜형으로 정규화했다.
- 영향: 중단된 `collect` 실행을 같은 명령으로 다시 시작할 수 있다. 기존 캐시 파일을 삭제할 필요는 없다.
- 검증: 전체 단위 테스트 24개 통과. 캐시 재실행 후 Parquet의 날짜 열이 날짜형인지 확인하는 회귀 테스트를 추가했다.

### 2026-08-26 - 구조화 공모가 검증과 재실행 캐시

- 커밋: `ce46ae4` (`Cache IPO history and verify structured DART prices`)
- 문제: 신고서 원문 정규식은 `확정공모가` 설명 문장 뒤의 `1주당` 같은 숫자를 가격으로 오인할 수 있었다. 또한 전체 수집을 반복하면 이미 수집한 KRX 가격·지수와 DART 원문까지 다시 호출했다.
- 변경:
  - 동일 접수번호의 OpenDART 지분증권 구조화 모집가액을 원문 값과 대조한다.
  - `[발행조건확정]` 신고서이며 구조화 값이 확인되면 `verified_structured_api` 또는 `verified_text_and_structured` 상태로 학습 후보에 포함한다.
  - 원문과 구조화 값이 다르면 `needs_review_structured_mismatch`로 감사 대기열에 남기고 학습·백테스트에서 제외한다.
  - KRX 상장 캘린더·상장일 가격·지수 이력과 DART 접수번호별 결과를 캐시한다. 완료된 과거 연도와 가격이 완성된 종목은 재호출하지 않고, 마지막 연도와 DART 공시 목록은 갱신한다.
  - DART 원문이 존재하지 않는 `014` 접수번호는 실패 로그에 보관하고 재호출하지 않는다.
  - 상장일보다 400일 이상 오래된 신고서는 연결 후보에서 제외해 재상장·동명 종목의 잘못된 연결을 줄였다.
- 영향: 첫 업그레이드 실행은 기존 DART 행에 구조화 검증 근거를 한 번 보강한다. 그 후 실행은 새 상장·새 접수번호·누락 가격 중심으로 짧아진다.
- 검증: 전체 단위 테스트 24개 통과. 구조화 값 사용, 비확정 신고서 격리, 캐시 재사용을 테스트했다.
- 다음 확인: 재수집 후 `data/processed/data_collection_summary.json`의 `open_target_rows`, `close_target_rows`, `offering_price_needs_review_rows`를 기록한다.

### 2026-08-26 - 공모가 감사·수동 검토 체계

- 커밋: `baf2086` (`Add auditable IPO offering price verification`)
- 변경: 공모가를 범위 규칙으로 자동 삭제하지 않고, 회사명·접수번호·원문 주변 문구·희망 밴드·수요예측 대조 결과를 감사 파일에 남기도록 했다.
- 산출물:
  - `ipo_predictor/data/raw/dart_offering_price_audit.parquet`
  - `ipo_predictor/data/raw/dart_offering_price_review_queue.parquet`
  - `ipo_predictor/data/manual/offering_price_overrides.csv` (사람이 승인한 값)
- 규칙: 100원 미만 또는 희망 밴드 밖의 값은 차단이 아니라 경고다. `needs_review_*`와 `missing`은 수동 승인 전 학습·백테스트에서 격리한다.

### 2026-08-26 - 실제 데이터 수집 안정화

- 커밋: `1ad0923` (`Harden IPO collection and validate offering prices`)
- 변경: DART 원문·수요예측·공모가 밴드·재무 데이터 수집 중 정상적인 결측과 실패를 구분하고, 불완전한 값은 0으로 채우지 않고 결측으로 보존하도록 했다.
