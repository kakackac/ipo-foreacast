4. 2026-09-04 이후 실제 신규·정정·철회 일정을 DART/KRX 공식 원천에서 갱신하고, 앞으로의 신규 결과를 전향 평가 대상으로 축적한다. 필요한 경우 이 단계에서 DART/KRX 인증 API 접근을 확인한다. 키를 채팅/문서/커밋에 넣지 않는다.
5. 데이터 버전 검토 후에만 시간순 개발 검증을 진행한다. 단순 평균/중앙값 기준선과 시초가·종가 모델을 비교하고 유형/연도별 오차와 불확실성을 보고한다. 기존 27건 평가 실험은 연구 신호 기준 미통과이며 홀드아웃은 이미 사용됐다. 새 모델의 독립 평가로 재사용하지 않는다. 이번 확인에서는 학습/성능 평가/배포 승인을 하지 않았다.
6. 아래 운영 자동화·Django 백엔드·모바일·출시 작업을 진행한다. 현재 확인된 모델 구현은 scikit-learn GradientBoosting 계열이며 FastAPI 예측 계층과 개별 운영 스크립트가 존재한다. 계정·결제 등을 갖춘 Django 프로젝트/완성 모바일 앱/배포 연결은 확인되지 않았다. 스팩 등 일반청약 가능 상품 확장은 별도 유형 정책/검증으로 다루고 일반 IPO 연구 코호트에 무분별하게 합치지 않는다.

유지 정책: 개인청약 경쟁률 수집/모델 입력 제외, 민간 사이트 수집 제외, 코넥스 제외, 통합 의무보유확약 사용, 상장일 21시 결과 수집/검증. 실시간 시세 서비스 계약은 보류 상태다. 일정 수집과 개인청약 경쟁률 수집은 서로 다른 작업이며 예정 IPO의 청약 일정은 계속 서비스 대상이다.

2026-10-04 실제 표본 후 갱신: 재무 연간 API만으로 5개 표본이 모두 실패한 원인을 확인하고 공식 DART 투자설명서의 재무 절 보완 경로를 연결했다. 실제 5/5 원문 대조 및 핵심 재무 복구, 전체 테스트 207개 통과. `--financial-documents-only` 모드는 키 없이 공개 원문으로 실행 가능하다. 다음 남은 데이터 작업은 이 재무 단독 경로의 전체 기간 적용과 원인별 결측 집계다. 기존 '키가 없어 표본 검증 대기' 상태는 이 재무 절 표본에 대해서 해소됐지만, 인증 API status=100 재현 및 전체 재무 복구는 별도 미완료다. 모델 학습/배포 승인 없음.

2026-10-04 추가 진행: 기존 공식 관측값으로 상장 전날 연구 데이터 390건(개발 363건)을 실제 생성했다. 재무의 접수번호/통화/회계 기준을 버리던 연결 결함과 DART 요청 제한을 자료 없음으로 처리하던 오류를 수정했다. 재무 단독 수집에서 연구 저장까지 코드를 연결했으며 전체 테스트 196개가 통과했다. 현재 키가 없어 실제 재무 표본 수집·전체 복구는 대기 상태다. 다음 실데이터 명령은 `collect-financials --financial-limit 5`이며 상세 절차는 감사보고서를 따른다. KRX 가격과 IPO 원문 전체 재수집은 이 단계에 필요 없다. 수요예측 전 데이터셋 및 전체 제품 피처 검증은 남아 있다.

2026-10-04 확인 기준이다. 수집기·파서·감사·일부 모델 실험·FastAPI 예측 API는 있지만, 운영 가능한 데이터와 승인된 모델을 갖춘 출시 서비스는 아직 아니다. 현재 저장소에서 Django 프로젝트, 모바일 앱, 배포 설정의 완성된 연결을 확인하지 못했다. 테스트 개수는 진행률이나 배포 준비율이 아니다.

반복 대화가 길어진 이유는 개별 파서 수정과 표본 감사가 하나의 운영 파이프라인 완성으로 이어지지 않았기 때문이다. 이후 완료 보고는 아래 산출물과 통합 검증을 기준으로 한다. 단순 파일 추가나 승인 차단만으로 데이터 문제가 해결됐다고 표현하지 않는다.

6개 묶음 모두 완료 기준이 남아 있다. 따라서 '거의 끝났다'거나 잔여율을 임의로 수치화할 근거가 없다. 데이터 파이프라인 안정화와 계정·결제·게시판까지 포함한 전체 앱 출시는 서로 다른 규모의 목표다.

정확한 대화 횟수·완료 날짜는 산정할 수 없다. 한번의 긴 작업에서 여러 항목을 처리할 수 있지만 실제 원천 접근, 데이터 결함, 외부 계정/배포/심사 및 새 IPO 결과 축적은 대화 횟수와 무관하다. 다음 일정 추정은 1번의 통합 데이터셋이 생성되고 백엔드·앱의 구체적인 구현 범위가 확정된 뒤 작업별 검증량을 바탕으로 갱신한다. '계속' 메시지 횟수를 목표로 삼지 않는다.

## 이번 서비스 안전장치 수정

기존 API는 모델 로드 실패 시 합성 데이터로 데모 모델을 학습해 예측을 반환했다. 이 경로를 제거했다. 누락 시장 지표/최근 IPO 수익률도 0이나 10으로 생성하지 않고 NULL로 유지해 훈련 시 저장된 결측 보정 정보만 사용한다.

운영자는 MODEL_DIR/production_release.json에 검토된 승인 정보를 별도로 관리해야 한다. 승인 true, prediction_stage, release_id, reviewed_by, validation_report와 정확한 두 모델의 pkl 및 meta.json SHA-256이 필요하다. 파일명은 고정된 단계별 open/close_v1 4개로 제한한다. 이번에 승인 파일을 만들거나 모델을 승인하지 않았다.

승인 파일은 신뢰할 수 있는 운영자가 관리하는 설정이며 모델 성능을 자동 증명하거나 암호학적 서명을 검증하는 장치는 아니다. 승인 파일과 모델 디렉터리는 외부 사용자 쓰기를 금지해야 한다. 매 모델 접근 시 승인·파일 해시를 다시 확인하므로 승인 철회나 파일 변경 시 기존 메모리 캐시도 무효화한다.

- /health: 서버 프로세스 응답 상태. 모델 승인과 무관하다.
- /ready: 승인 모델의 실제 로드가 가능할 때만 200, 그 외 503.
- /predict, /predict/batch, /model/info: 승인 모델이 없으면 503. 요청 처리 중 학습하지 않는다.
- 응답과 로그에 예외 원문을 출력하지 않고 고정 메시지/예외 유형만 남긴다.

이 안전장치는 실서비스 오인 방지이며, 입력 원천/공개 시점까지 검증하는 서비스 어댑터나 인증·과금·부하·배포 검증의 대체물이 아니다.
