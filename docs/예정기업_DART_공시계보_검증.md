## 선택 규칙

1. 달력의 corp_code와 뷰어의 openCorpInfoNew 고유번호가 정확히 일치해야 한다. 회사명만으로 연결하지 않는다.
2. 요청한 접수번호가 본문 선택창에서 실제 선택돼 있어야 하며, 지분증권 신고서여야 한다.
3. 본문 계보의 공시일과 문서 종류를 함께 검사한다. 더 최근의 효력발생안내를 최신 증권신고서로 선택하지 않는다.
4. 계보 내 최신 날짜의 신고서가 요청 접수번호와 다르거나 여러 후보이면 검토 대기로 돌린다. 이번 20건은 이 상태가 없었다.
5. 본문 목차에서 정확히 '요약정보'인 항목을 찾고 접수번호 및 숫자 조회 인자를 검증한다. 페이지 JavaScript는 실행하지 않는다. 다른 목차의 첫 숫자나 마지막 숫자를 추정하지 않는다.
6. 원문이 없거나 회사/접수번호/목차가 불일치하면 오류 유형만 기록하고 자동 승인을 차단한다. 인증정보·쿠키·요청 헤더와 예외 메시지는 감사 결과에 쓰지 않는다.

## 확인 범위의 한계

'최신'은 조회 시점 해당 뷰어 본문 계보에서 관측한 최신 신고서다. 회사의 모든 공시를 별도 검색해 누락 계보까지 배제한 것은 아니며 이후 정정·철회는 재확인해야 한다. 효력발생은 공시 내용의 정확성 또는 상장을 보장하지 않는다.

요약의 신규상장 문구만으로 일반 IPO/스팩/이전상장 분류를 자동 승인하지 않았다. 확정 상장일, 수요예측 완료 여부, 기관 경쟁률·통합 확약은 별도 원문 항목과 공개시각 검증이 필요하다. 이번에는 원문 구조와 계보를 확보했으며, 기존 모델 피처나 이미 사용한 2026년 최종 평가 표본은 변경하지 않았다.

DART 청약 달력은 청약 일정 발견 원천이다. 상장 예정일 전체의 완전한 목록을 보장하지 않으며, 기존 상장사의 다른 증권 청약도 포함한다. 따라서 DART의 일정·신고서와 KRX/KIND의 상장 이벤트를 연결하는 정책은 유지한다.

## 실행

```bash
python ipo_predictor/scripts/audit_upcoming_disclosures.py \
  --calendar ipo_predictor/data/raw/dart_calendar_audit/20260922T171858223042 \
  --output ipo_predictor/data/raw/upcoming_disclosure_audit
```

현재 스크립트는 20종목 표본 감사용이다. 전 기업 무제한 크롤러 또는 운영 스케줄러가 아니다. 이번 실제 수집은 이미 완료했으므로 같은 검증을 위해 사용자가 재실행할 필요는 없다.

## 청약 일정 원장 생성 결과

build_upcoming_schedule_registry.py로 저장 원문을 재처리했다. 20건 모두 요약 표의 청약 시작·종료일이 달력과 일치했다. 결과는 ipo_predictor/data/processed/upcoming_schedule_registry/20260922.json에 저장했다. 후보 ID는 회사 고유번호와 접수번호를 함께 사용하며 날짜·표 위치·원시 값·원문 해시·조회 시각을 보존한다. 출력은 기존 파일을 덮어쓰지 않는다.

- 일정 승인: 20건. 거절: 0건. 모델 승인: 0건.
- 청약 기간은 2026-10-01 시작 멜콘부터 2026-11-10 시작 하나에어로다이내믹스까지 확인했다. 사진 D-day로 날짜를 역산하지 않았다.
- 모집가액 표 숫자는 확정가로 간주하지 않는다. 멜콘의 10,700원은 희망공모가액 10,700~12,300원 중 하단 기준이다. 스팩의 2,000원도 이 표만으로 최종 확정 승인하지 않는다.
- 일반공모·보통주 표기는 일반 IPO/스팩/이전상장 구분을 대체하지 않는다. 상장일은 이 원장에서 확인하지 않았으므로 NULL을 유지한다.
- 공개 일정 확인과 투자 예측 승인은 별개다. 정정·철회 감시, 세부 유형, KRX/KIND 종목코드·상장일 연결, 단계별 피처 검증은 남아 있다.

회귀 검증은 전체 167개 테스트 통과, 기존 경고 3개다. 날짜 오류·표 중복/병합·달력 불일치·계보 변경·해시 변경 시 자동 승인을 차단한다. 이 통과는 전체 IPO 모집단 또는 서비스 배포 승인과 다르다.
