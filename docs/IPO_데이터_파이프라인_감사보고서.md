### 시장 지수와 모델 입력

실제 KOSPI·KOSDAQ 원본의 마지막 날은 2026-09-09다. 신규 IPO에 이 오래된 마지막 값을 그대로 사용하면 상장 직전 시장 지표가 아니다. `collect-event-context`는 현재 상장 전날 21시 연구 계약에 필요한 KOSPI만 2026-09-10~11-02의 38개 평일 기준일에서 조회한다. 11월 2일 종료는 날짜만 있는 지수의 가용시각을 다음 날 00시로 두는 기존 연구 계약을 따르기 때문이다. KOSDAQ/실시간 시세 상품 확대나 DART/종목 가격 재수집이 아니다.

날짜별 성공 응답의 지수명·실제 기준일·양수 종가를 검사해 공개 필드만 해시 체크포인트로 저장한다. 오류/블록 없는 응답을 빈 거래일로 저장하지 않고, 부분 실패 후 완료 날짜는 재호출하지 않는다. 빈 공식 응답은 숫자 행을 생성하지 않으며 전체 빈 응답은 추가 검토 상태다. 빈 응답을 휴장일로 확정하지 않는다. 체크포인트 재사용은 원천 데이터의 날짜별 완전성에 대한 독립 거래 달력 감사까지 대체하지 않는다.

기존 연구 입력 계약으로 출처/공개시각·공식 시가/종가 타깃을 연결했다. 기관 관측값은 각각의 실제 접수번호에 속한 공시일을 사용하고, 최근 IPO 지표는 상장 전 이미 결과가 알려진 검증된 과거 타깃에서만 재계산한다. 같은 행을 과거 데이터에 중복 추가하지 않으며 스팩은 일반 IPO 모델에서 분리한다. 이번 신규 모델 입력은 **상장 전날 21시의 사후 재구성**이지 원래 제품의 pre_demand/post_demand cutoff 완성이나 새로운 독립 테스트가 아니다.

현재 실제 실행은 키가 없는 환경에서 오프라인 연결까지 완료했고 버전 `2371b9c1e9e7e18a9bb1`에 일반 16건 `market_context_not_collected`, 스팩 5건 `separate_spac_policy_not_general_model`을 저장했다. 준비 데이터는 0행이며 예측/성능은 산출하지 않았다. 모의 지수 응답으로 수집→입력 1개 일반 IPO 준비/스팩 분리→재실행 미호출의 통합 회귀 경로를 테스트했지만 이것을 실제 지수 수집이나 신규 16건 입력 완료로 계산하지 않는다.

### 원인 수정과 검증 결과

1. **규정 주석에 의한 조기 종료:** 일반기관 배정 규정의 '15일 확약 시 30% 이상 배정' 같은 문구를 확약 결과 행으로 오인하고, 미승인 상태에서 탐색을 끝내던 결함이다. 기간 행의 첫 셀 라벨을 명확히 구분하고, 미승인 표에서는 다음 실제 결과 표를 탐색한다.
2. **영(0) 표기 및 분모:** 기간 수량의 `-`를 바로 결측/0으로 처리하지 않는다. 명시적 합계 수량 열, 별도 수요예측 표의 총 신청수량, 확약 합계+미확약=총수량을 모두 대사할 때만 0 해석을 승인한다. 빈 문자열·불완전 표·다른 분모는 계속 거절한다.
3. **기관 문맥의 위치:** 티앤이코리아의 합계 경쟁률 1,041.02는 표 안에 기관이라는 단어가 없지만 바로 앞 '수요예측 참여 내역' 제목과 운용사(집합)/운용사(고유)/투자일임사 열로 범위가 명확하다. 이 제목+열 구조를 함께 확인하는 경로를 추가했으며 일반/개인청약·비례배정은 차단한다.

공지 원장은 `event_id`, URL, 게시 시각, 공모가, 청약 기간, 정정 여부, 이전 공지 ID, 원문 해시와 버전 ID를 보존한다. 이벤트 ID에 KRX 회사명·주관사·상장일·공모가를 대조하고, 청약 기간 또는 공모가 대조값이 비어도 자동 승인은 하지 않는다. `게시 시각 < 예측 시점 < 상장일`을 만족하는 값만 해당 시점 모델에 전달한다. 정정은 기존 값을 덮어쓰지 않고 새 버전으로 추가한다. DART 수요예측의 기관 경쟁률·확약도 최초 신고서 날짜가 아닌 수요예측 공시 접수일을 피처별 `available_at`으로 사용한다.

공식 원천을 확인해도 값이 없으면 `official_source_not_published`, 아직 공개 전이면 `not_yet_published`, 표를 읽지 못하면 `parser_failed`, 접근에 실패하면 `source_access_failed`로 분리한다. 모든 상태에서 수치는 NULL이며, 결측 플래그·사유·확인 원천·확인 시각을 보존한다. 0·평균·중간값은 원시 데이터에 기록하지 않는다.

모델은 정보 공개 단계별로 분리한다.

| 모델 | 허용 입력 | 현재 상태 |
|---|---|---|
| `pre_demand` | 공모 구조·최대주주 보호예수·주관사·시장 상황 | 평균 충족률 66.4%, 핵심 공모 구조 피처 부족으로 차단 |
| `post_demand` | 확정 공모가·희망 밴드 위치·기관 경쟁률·기간별 확약 추가 | 평균 63.3%, 기관 경쟁률·희망 밴드 부족으로 차단 |

이 분리는 아직 모델 성능을 뜻하지 않는다. 각 단계는 일반 IPO, 검증 공모가·시초가·종가 타깃, 필수 피처 평균 70% 이상, 단계별 핵심 원천 피처 60% 이상, 상장 후 공개 피처 0건을 모두 충족해야만 학습·백테스트를 시작할 수 있다.

### 1.4 과거 세 단계 설계 기록과 현재 두 단계 정책 (2026-08-28, 2026-09-07 갱신)

**현재 정책:** 개인 청약 경쟁률과 `post_retail`은 모델·CLI·학습 데이터셋에서 제외됐다. 아래의 `post_retail` 설명은 당시 설계 검토의 기록이며 현재 구현·운영 기준이 아니다. 현재 모델 계약은 `pre_demand`, `post_demand` 두 단계뿐이다.

세 공개 단계 모델은 표본을 분할하지 않는다. 동일 IPO의 검증된 상장일 시초가·종가 타깃을 공유하고, 각 행에서 예측 기준 시점에 공개된 피처만 선택한다.

| 단계 | 공통 타깃 | 추가로 허용되는 정보 | 학습 판단 |
|---|---|---|---|
| `pre_demand` | 공모가 대비 상장일 시초가·종가 수익률 | 공모 구조, 보호예수, 주관사, 위험요소, 상장 전 시장 | 수요예측·개인청약 결측은 정상이나 해당 단계 핵심 피처와 시점 검사는 통과해야 함 |
| `post_demand` | 동일 | 확정 공모가, 기관 수요예측 경쟁률, 의무보유확약 | 기관 경쟁률·확약의 공식 원천과 공개시각이 확인돼야 함 |

현재 데이터 수집은 한 번 수행하고, 수집 결과에서 두 단계 데이터셋·유형별 준비도·피처별 공개시각 검사를 생성한다. 모델 학습과 시간순 백테스트는 각 단계가 품질 기준을 통과했을 때만 실행한다. 개인 청약 경쟁률은 수집·준비도·학습 기준에 포함하지 않는다.

`train`과 `backtest`는 요청한 `--prediction-stage`의 전용 데이터셋을 우선 읽는다. 그 데이터셋에서 상장일 이후 공개되었거나 공개시각을 검증할 수 없는 값이 있는 행은 그 단계의 학습 후보에서 제외된다. 다른 단계 데이터셋에 영향을 주지 않는다.

일반 청약 가능 공모를 넓게 서비스 범위에 포함하는 방법은 다음과 같이 비교한다.

| 방법 | 판단 |
|---|---|
| 모든 유형을 일반 IPO 모델에 그대로 합침 | 채택하지 않음. 스팩·외국기업·리츠의 공모 구조와 수익률 분포 차이를 무시한다. |
| 단일 통합 모델 + 공모유형 이진 피처 + 유형별 백테스트 | 조건부 채택. 일반 보통주, 스팩, 외국기업 보통주처럼 공식 일반청약이 확인된 유형만 후보에 두고 유형별 표본·오차·방향 정확도를 별도 공개한다. |
| 유형별 별도 모델 | 장기 확장안. 유형별 검증 표본과 핵심 피처 충족률이 충분해졌을 때만 만든다. |
| 계층형/멀티태스크 모델 | 연구 확장안. 소수 유형의 통계적 정보를 일부 공유할 수 있으나, 현재 표본·검증 체계에서 먼저 도입하지 않는다. |
| 서비스 목록은 전체, 예측은 준비된 유형만 | 현재 운영 원칙. 사용자는 일반청약 적격 후보를 확인할 수 있고, 근거가 부족한 유형은 수치 예측 대신 준비 상태를 본다. |

`offering_type` 원문은 이벤트 마스터와 피처 행에 보존한다. 모델에는 임의의 순서를 만들지 않도록 상장 전 DART 신고서 회사명으로 확인되는 스팩 여부만 독립 이진 피처로 넣는다. KIND 사후 이벤트 마스터에 의존하는 외국기업 분류는 유형별 평가·운영 정책용이며 상장 전 모델 입력으로 쓰지 않는다. 일반/스팩은 KIND 신규상장 정보만으로 일반청약을 확정하지 않는다. 공식 주관사 공지의 통합 일반청약 결과가 이벤트와 정합될 때만 `retail_subscription_eligible=true`으로 승격하며, ETF·ETN·펀드·리츠 등 비대상은 명시적으로 제외한다.

일반청약 경쟁률은 전체 통합값 한 개만 모델 입력으로 쓴다. 주관사별 당사 경쟁률과 비례 경쟁률은 감사용 원시 데이터로 보존하되 모델에 넣거나 평균내지 않는다. 공동주관사 통합값은 모든 참여사의 동일 기준 청약주식 수와 일반청약 배정물량이 확인될 때만 `청약주식 수 합계 / 배정물량 합계`로 재구성할 수 있다.

`통합경쟁률`이라는 단어 하나도 자동 승인 근거로 충분하지 않다. 한 증권사 내부의 균등·비례 청약을 합친 값일 수 있으므로, 같은 원문 블록에서 `전체 참여 증권사`, `전체/모든 주관사`, 또는 `공동주관사 합산`처럼 전체 참여기관 범위를 명시해야 한다. 범위가 없으면 값·원문 해시는 감사용으로 보존하되 `underwriter_only_or_unknown`으로 격리한다. 공식 안내를 확인한 결과 한국투자증권과 미래에셋증권은 현재 청약/개인 거래 화면 중심이고, NH투자증권의 공개 과거 결과 경로는 미검증이다. KB증권은 공개 PDF 공지가 있으나 문서별 범위 확인이 필요하다. 따라서 네 주관사 모두 현 시점에는 수동 URL 연결만 허용하며 로그인 자동화·URL 추측은 하지 않는다. [한국투자증권 경쟁률 안내](https://securities.koreainvestment.com/pro_help/7327.html), [미래에셋증권 공모주 안내](https://securities.miraeasset.com/public/mw/guide/html/notice01.html), [KB증권 청약 결과 안내](https://www.kbsec.com/go.able?linkcd=s020701090000)

공식 URL 연결을 반복 가능한 운영 작업으로 만들기 위해 `prepare-underwriter-review-queue` 명령을 추가했다. 저장된 KRX 이벤트 마스터만 읽어 지원 주관사의 일반 IPO·스팩·외국기업 상장 후보에 대해 회사명, 상장일, 공모가, 주관사, 공식 안내 URL, 수집 정책, URL 연결 상태를 CSV/Parquet 대기열에 기록한다. 이 명령은 주관사 웹사이트를 호출하지 않고 URL을 생성하지도 않는다. 검토자가 공개 공식 공지의 실제 URL·게시일·공모가·청약 기간을 확인한 뒤에만 기존 공식 공지 원장으로 옮긴다.

### 1.5 DART 발행실적보고서 범위 감사 (2026-09-04)

KRX의 [신규상장기업현황](https://kind.krx.co.kr/listinvstg/listingcompany.do?method=searchListingTypeMain)은 상장 이벤트와 공모 관련 기본 정보를 제공하지만 개인 청약 통합 경쟁률을 공통 열로 제공하지 않는다. DART도 개인 일반청약 경쟁률의 구조화 표준 필드를 제공하지 않는다. 이번 실제 수집에서 상장 전 `증권발행실적보고서` 후보 765건을 찾았지만 개인청약 승인 행은 0건이었다. 대표 원문인 [엔에스쇼핑 증권발행실적보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20150320000046)는 `일반공모에는 기관투자자의 청약이 포함되어 있습니다`라고 명시한다. 따라서 일반공모 청약현황은 개인 일반청약 경쟁률의 대체값이 될 수 없다.

현재 DART 처리 원칙은 아래와 같다.

1. 동일 DART 고유번호의 `증권발행실적보고서` 중 상장일 전 접수본을 찾아 공시 계보와 원문 범위를 감사한다.
2. 기관 청약 포함 문구가 있으면 `dart_offering_result_institutional_included_not_retail`로, 일반공모 청약현황 표면 `dart_offering_result_general_offering_not_retail_scope`로 기록하고 모델 입력에서 제외한다.
3. 예외적으로 `전체 일반청약자 경쟁률`이 직접 명시되고 기관 포함 문구가 없는 경우만 개인 경쟁률 후보로 보되, 현재 실제 수집에서는 해당 행이 없었다.
4. 개인 일반청약 경쟁률은 이벤트 정합·게시시각·공모가·청약기간을 검증한 주관사 공식 결과 공지에서만 승인한다.

`dart_offering_result_audit.parquet`에는 DART 접수번호, 접수일, 원문 URL, 범위 판정, 근거 문구와 파서 버전을 남긴다. 원문 ZIP 014·통신 실패는 별도 파일에 접수번호별로 보관하고 TTL 후 재시도한다. 기관 포함/범위 확인 완료 행은 같은 파서 버전에서 캐시를 재사용한다.

현재 로컬 이벤트 마스터로 생성한 주관사 공지 대기열은 594건이다. 한국투자증권 182건, 미래에셋증권 172건, NH투자증권 154건, KB증권 86건이며 공식 URL 연결 완료 행은 0건이다. 이는 값 수집률이나 학습 표본이 아니라, 개인 경쟁률을 확인할 공식 결과 공지 연결 작업량이다.

### 1.6 일반청약 경쟁률의 범위별 승인 규칙 (2026-09-04)

청약 경쟁률은 숫자보다 **범위(scope)** 가 먼저다. 특히 `통합경쟁률`은 공동주관사 전체 일반청약 경쟁률이라는 보장이 없으며, 특정 증권사 내부 균등·비례 청약을 통합한 표현일 수 있다. 따라서 아래 세 경로만 모델 입력으로 승인한다.

| 승인 경로 | 자동 승인 조건 | 시스템 처리 |
|---|---|---|
| 전체 범위 직접 공시 | `공동주관사 전체`, `전체/총 일반청약`, `통합 일반청약`, 전체 참여 증권사/주관사 합산 중 하나와 `숫자 : 1`이 같은 표 행·문단에 직접 연결 | `official_notice_integrated_retail_ratio` |
| 원시 수치 재구성 (조건부) | 전체 일반청약 경쟁률이 원문에 직접 없고, 모든 참여 증권사의 공식 문서에서 `청약주식 수`와 `일반배정 주식 수`를 파싱하며 참여사가 빠짐없이 확인됨 | `청약주식 수 합계 / 일반배정 주식 수 합계`로 계산 후 `official_notice_reconstructed_retail_ratio` |
| 단독 일반청약 접수처 | 공식 문서에서 `단독주관`, `단일 일반청약 접수처`, `유일 일반청약 접수처` 중 하나와 경쟁률이 직접 연결 | `official_notice_single_retail_intake_ratio` |

URL 원장은 숫자 입력 양식이 아니다. 문서 URL, 게시 증권사, 공식 원문으로 확인한 참여 증권사 목록, 확인 상태만 보관한다. 시스템은 원문 표에서 수치와 `주` 단위를 직접 읽어 감사 파일에 근거 문구와 함께 저장한다. 참여사 한 곳이라도 빠지거나 중복되고, 참여사 목록이 문서 연결과 불일치하거나, 배정 물량이 없으면 계산하지 않는다. [KB증권 공개 공지 표본](https://m.kbsec.com/go.able?idt=20260703&linkcd=s060300010000&seq=10010069)에는 `일반배정 주식수`, `청약주식수`, `비례배정 경쟁률`이 함께 있지만 전체 일반청약 경쟁률은 직접 표시되지 않았다. 따라서 비례 경쟁률은 별도 감사값으로만 보관한다. 증권사별 경쟁률의 단순 평균, 한 곳의 당사 경쟁률, 균등·비례 내부 통합값, 범위 없는 단순 경쟁률은 계속 모델 입력에서 제외한다.

### 1.7 KRX 상장일 가격 미매칭 감사 체계 (2026-09-04)

이전 `상장일 가격을 찾지 못했습니다` 로그는 “KRX 일별 시세 응답에서 이벤트의 코드·표준코드·회사명을 찾지 못했다”는 뜻이지, 상장일 가격 자체가 없다는 뜻이 아니다. 이제 각 이벤트의 결과를 `krx_listing_price_audit.parquet`에 저장하고 다음처럼 구분한다.

| 상태/사유 | 의미 | 후속 처리 |
|---|---|---|
| `matched` + 표준코드/종목코드 | 지정 시장의 KRX 일별 행으로 직접 확인 | 시가·종가 타깃 사용 가능 여부를 별도 검증 |
| `*_market_mismatch_recovered` | 지정 시장에서 못 찾았으나 반대 시장 행으로 복구 | 시장 변경/이벤트 정보 불일치로 감사, 가격은 원천 근거와 함께 보존 |
| `daily_price_api_response_empty` | 조회한 시장의 해당 일자 일별 시세 목록이 비어 있음 | API 제공 범위·상품·비거래일을 확인. 가격 부재로 단정 금지 |
| `daily_rows_code_and_company_name_unmatched` | 일별 행은 있으나 코드와 회사명이 모두 맞지 않음 | 당시 거래코드·재상장·이전상장·우선주/종류주 가능성을 검토 |
| `daily_rows_code_unmatched_company_name_unavailable` | 일별 행은 있으나 이벤트 회사명이 없어 보조 대조를 못 함 | 회사명/표준코드 보강 전 자동 연결 금지 |

조회 시장, API 행 수, 매칭 방식, 실패 사유와 사람 검토 필요 여부를 함께 남긴다. 따라서 향후 실제 수집 결과에서는 경고 개수 대신 이 감사 원장의 사유별 건수로 가격 품질을 판단한다.

### 1.8 현재 우선순위: 개인청약 경쟁률 제외, 수요예측 후 모델 우선 (2026-09-04)

**갱신:** 이후 결정으로 개인청약 경쟁률은 후순위 실험이 아니라 현 모델·수집 범위에서 완전히 제외됐다. 아래 문단의 `post_retail`·`--include-retail-audit` 언급은 당시 검토 기록이며 현재 실행 정책으로 사용하지 않는다.

개인청약 경쟁률은 상장 전에 공개되기는 하지만 일반청약 마감 이후에야 확정된다. 출시 초기 예측의 기본 시점을 수요예측 결과 공개 후로 두면 확정 공모가·기관 수요예측·의무보유확약까지 활용할 수 있고, 개인청약 경쟁률은 필수 입력이 아니다. 따라서 기본 모델은 `post_demand`이며 개인청약 경쟁률은 피처·수집·준비도 기준에서 제외한다.

개인청약 경쟁률 관련 원시 감사 파일과 내부 호환 코드는 과거 조사 기록으로 보존하지만, CLI에는 이를 켜는 옵션이 없고 모델 피처·준비도·학습 데이터셋에도 포함하지 않는다. 이는 개인청약 경쟁률의 유용성을 부정하는 주장이 아니라, 현재 서비스의 예측 시점과 공식 원천 검증 범위에서 제외한다는 운영 결정이다.

### 1.9 KRX 상장일 가격 해소 절차와 종료 기준 (2026-09-04)

상장일 가격의 확인 절차는 다음 순서로 고정한다.

1. KRX KIND 이벤트의 상장일·시장·종목코드·표준코드·회사명을 정규화한다.
2. 해당 날짜 KOSPI/KOSDAQ KRX OpenAPI 원시 응답을 조회하고, 표준코드, 종목코드, 회사명 순으로 재매칭한다. 지정 시장에 없을 때만 반대 시장을 확인한다.
3. 매칭된 행의 실제 코드·ISIN·회사명·시장과 시장별 응답 행 수·SHA-256 해시·식별 열 표본을 `krx_listing_price_audit.parquet`에 기록한다.
4. 재상장·이전상장 검토·우선/종류주·리츠/ETF/ETN 등은 가격 미매칭 원인과 별개로 `excluded_non_target_event`로 분리한다.
5. 일반 IPO에서 공식 일별 응답이 양 시장 모두 비었다는 증적이 있을 때만 `official_price_unconfirmed`으로 종료한다. 응답이 있으나 식별자가 맞지 않는 경우는 `historical_identifier_review_required`이며 자동 제외나 가격 부재 확정이 아니다.

이제 수집 요약은 단순 경고 개수 대신 `official_price_verified`, `official_price_unconfirmed`, `historical_identifier_review_required`, `historical_price_cache_reaudit_required`, `excluded_non_target_event`별 건수를 출력한다. 실제 재수집 후에만 각 상태의 실측 건수를 보고한다.

### 1.10 가격 타깃 승인 게이트 (2026-09-04)

상장일 가격의 원시값 보존과 모델 타깃 승인은 별도다. `open_price`, `close_price`가 존재하더라도 `price_resolution_status`가 `official_price_verified`가 아니면 `open_return_pct`, `close_return_pct`를 만들지 않는다. 가격이 있어도 근거가 없는 과거 캐시·식별자 불일치·공식 응답 미확인·비대상 이벤트는 `price_target_validation_status=blocked_nonverified_krx_listing_price`로 남긴다.

`official_price_verified`는 KRX 일별 원시 응답 근거가 저장되어 있고, KIND 이벤트의 표준코드·종목코드·회사명 중 허용된 식별자로 직접 매칭된 경우에만 부여한다. 원시 응답 근거가 없는 이전 캐시는 자동으로 검증 완료로 승격하지 않고 다음 `collect`에서 KRX 일별 API 재조회 대상으로 보낸다. 재조회 뒤에도 근거를 얻지 못한 행만 `historical_price_cache_reaudit_required`로 분류한다. 이 게이트는 타깃 수를 줄일 수 있지만, 근거가 불명확한 가격으로 모델 성능을 과장하는 일을 막는 필수 조건이다.

### 1.11 피처 품질 집계와 학습 전 판정 (2026-09-04)

수집 결과의 피처 품질은 감으로 판단하지 않는다. `feature_coverage_audit.parquet`는 피처마다 전체 행, 값이 있는 행, 결측 행, 충족률, 출처 식별자 보유 행, 공개시각 보유 행, 사람 검토 필요 행을 기록한다. 결측 사유와 검증 상태의 분포는 JSON 열에 저장해 `official_source_field_unavailable_or_unverified`, `financial_publication_time_unverified`, `parser_failed` 같은 원인을 구분한다.

이 집계는 성능 수치가 아니다. 다음 실제 수집 뒤 `post_demand`의 기관 수요예측·희망 밴드·확약 피처 충족률과 `model_stage_readiness.json`의 후보 수를 함께 확인해, 최소 기준을 넘긴 단계만 학습 후보로 판단한다.

### 1.12 실제 수집 재감사와 KRX 유형 캐시 복구 (2026-09-07)

최근 실제 실행은 KRX 이벤트 1,513건, DART 정합 피처 행 765건, 시초가·종가 타깃 708건을 만들었다. 가격 감사 상태는 `official_price_verified` 1,101건, `historical_identifier_review_required` 226건, `excluded_non_target_event` 185건, `official_price_unconfirmed` 1건이다. 따라서 가격 타깃 708건은 원시 KRX 증거가 확인된 행만으로 만든 값이며, 226건의 식별자 불일치·185건의 비대상 이벤트를 가격 부재로 단정하거나 모델에 넣지 않았다.

수요예측 원문 `재시도 보류` 로그는 새 실패가 아니다. `dart_demand_document_failures.parquet`에 2026-09-04에 기록된 ZIP `014` 실패 15건이 있으며, 7일 재시도 간격 때문에 2026-09-11 전에는 재호출하지 않는다. `014`는 해당 접수번호의 ZIP이 없다는 의미이므로, 공시 계보 전체가 없다는 뜻이나 해당 기업을 영구 제외한다는 뜻이 아니다.

이번 재감사에서 이벤트 마스터 1,513건 중 1,471건의 `offering_type`이 비어 있고 `event_class`만 있는 과거 캐시 결함을 발견했다. 같은 KIND 원천 필드로 메모리 재분류한 결과는 다음과 같다.

| 유형 | 재분류 건수 | 처리 원칙 |
|---|---:|---|
| 일반 보통주 IPO | 986 | 일반 IPO 품질·시점 기준을 충족할 때만 학습 후보 |
| 스팩 IPO | 324 | 일반 IPO와 성능을 별도 집계, 혼합 학습은 별도 정책 없이는 금지 |
| 시장 이전 | 84 | 일반 IPO 타깃에서 제외 또는 개별 검토 |
| 재상장 | 74 | 일반 IPO 타깃에서 제외 |
| 리츠 | 23 | 비대상 |
| 외국 보통주 상장 | 18 | 별도 평가 전 일반 IPO 모델 입력에서 제외 |
| 우선/종류주 | 3 | 비대상/검토 |
| 검토 필요 | 1 | 자동 학습 제외 |

수정 후 `collect`는 이 분류를 `classification_rule_version=2`와 함께 캐시에 저장하고, 실행 매니페스트에 `classification_cache_repaired_rows`를 남긴다. 이 보정은 KIND에 이미 있던 상장유형·증권구분·국적·회사명만 다시 계산하는 것이므로, 새로운 데이터를 추정하거나 모델 입력을 임의로 채우지 않는다.

2026-09-07의 1/765(0.1%) 기관 경쟁률과 4/765(0.5%) 확약 결과는 별도 후보 공시를 넓게 탐색한 이전 정책의 결과다. 이 수치는 DART 전체가 기관 수요의 부적합 원천이라는 증거가 아니다. 최종 `[발행조건확정]증권신고서`는 대표주관사가 취합한 IPO별 통합 기관 수요예측·확약 표를 포함할 수 있으므로, 현재는 이 최종 DART 원문을 1차 원천으로 재판정한다. 유통가능물량 22.6%는 표본 감사에서 문맥 밖 자기주식·일반투자자 수량 오인이 발견되어 무효화했으며 파서 버전 4로 다시 판정한다. 새 원천 규칙으로 2015~2026 전체를 재수집하기 전까지는 여전히 모델 학습·백테스트·성능 주장을 금지한다.

### 1.13 DART 결측의 원인별 해결 규칙 (2026-09-07)

기관 경쟁률 1/765, 희망 밴드 95/765라는 결과를 단순히 "DART 데이터가 없다"고 결론 내리면 안 된다. 코드 감사를 통해 세 가지 서로 다른 원인을 확인했다.

| 문제 | 기존 결함 | 수정된 해결 규칙 |
|---|---|---|
| 희망 공모가 밴드 | 최신 발행조건확정 신고서 한 건만 선택해 최초/정정 신고서의 밴드를 잃음 | 공모가 확정은 최종 조건 문서에서만 승인하고, 밴드·공모 구조는 같은 DART 계보에서 값이 있는 가장 최신 사전 문서를 선택. 값별 접수번호·공개일 보존 |
| 기관 수요예측 경쟁률 | 후보 765건 중 한 접수번호만 파싱하고 좁은 문장 패턴만 적용 | 수요예측·발행조건확정·투자설명서·증권신고서 후보를 순서대로 검사. 기관/수요예측 문맥과 `숫자 : 1`이 같은 행/문장일 때만 승인 |
| 의무보유확약 | 기간 라벨 뒤 첫 숫자를 읽어 표의 다른 열을 오인할 수 있음 | 의무보유확약 표의 비율 열 또는 신청주식수 열과 합계 행이 확인될 때만 계산. 서로 다른 문서의 부분 기간은 병합 금지 |
| 유통가능물량 비율 | 신주+구주매출을 실제 유통가능물량으로 대체해 기존주주의 즉시 유통분을 누락 | 신고서가 직접 밝힌 상장 직후 유통가능 주식 수/비율만 승인. 공시값이 없으면 결측이며 신주·구주는 대체값으로 사용 금지 |

후보 문서별 파싱 결과는 `dart_demand_document_cache.parquet`에 접수번호, 제목, 접수일, 파서 버전, 추출 근거와 함께 저장한다. ZIP `014`는 접수번호별 실패 이력으로 남기고 다음 후보를 계속 검사한다. 따라서 재시도 보류는 후보 탐색의 종료 조건이 아니다.

이 수정은 실제 원문에 없는 기관 경쟁률·확약·유통가능물량을 추정하지 않는다. 유통가능물량 파서 버전 3의 넓은 120자 탐색은 무관한 수량을 오인할 수 있어 폐기했고, 버전 4에서는 라벨과 수량이 직접 연결되거나 `보호예수 및 매도금지물량을 제외한 N주` 계산식이 같은 문맥에 있을 때만 승인한다. 재수집 후 모든 계보 후보를 읽었지만 승인 규칙을 통과하는 값이 없으면 그 행은 `official_source_not_published_or_not_machine_readable`로 판단해야 하며, 기관 경쟁률·확약은 그때만 주관사 공식 수요예측 결과 공지가 필수 원천이 된다. 학습은 계속 금지한다.

### 1.14 원천 적합성 재판정과 전체 재수집 전 실행 정책 (2026-09-07, 정정)

**판정 정정: DART 구조화 API와 DART 원문은 구분해야 한다.** 지분증권 구조화 API에는 기관 경쟁률·확약 전용 필드가 없지만, 최종 `[발행조건확정]증권신고서` 원문에는 대표주관사가 취합한 IPO 단위의 통합 기관 수요예측·기간별 의무보유확약 표가 기재될 수 있다. 따라서 기본 수집이 이 최종 문서를 한 번 읽어 공모 구조와 통합 표를 함께 검증하는 것이 맞다. 다만 다른 제목의 후보 문서를 대량으로 넓게 훑어 우연한 `숫자 : 1`을 채우는 방식은 계속 쓰지 않는다.

| 피처 | 확정 원천 정책 | 다음 실행에서 할 일 | 현재 결론 |
|---|---|---|---|
| 희망 공모가 밴드, 신주·구주, 최대주주 보호예수, 재무 | DART 신고서·정정 신고서·구조화 정보 | 계보·표 파서의 표본 검증 뒤 전체 재판정 | DART 기본 수집 계속 |
| 유통가능물량 | DART 원문의 직접 공시 수량/비율만 | v4 규칙으로 2015~2026을 한 번 재수집해 충족률·오인 샘플을 확정 | 기존 173건/비율은 잠정값, 모델 사용 금지 |
| 기관 수요예측 경쟁률, 의무보유확약 | DART 최종 `[발행조건확정]` 원문의 직접 기재 통합 표 | 같은 접수번호의 기관 경쟁률·기간별 확약이 직접 연결됐는지 검증하고 접수번호·URL·근거 문구 저장 | 기본 수집에서 1차 수집·승인 |
| 위 DART 원문이 ZIP 014이거나 통합 표가 없음 | 대표주관사 공식 수요예측 결과 공지 | 해당 공지가 전체 기관 기준임을 문구로 검증 | 보조 원천 후보. 여러 공동주관사 수치를 합산·평균하지 않음 |

기본 `collect`는 각 IPO의 상장 전 DART 공시 계보를 탐색한다. 기관 경쟁률과 통합 확약은 같은 접수번호에 함께 있어야 한다는 제약 없이, 각각 공모가·회사·공개시점·명시적 기관 범위를 검증한 최신 문서를 사용한다. `--audit-dart-demand`는 호환용 옵션이며 기본 수집에서 이 계보 탐색은 항상 실행된다. 문맥이 다른 후보의 수치는 계속 감사 로그에만 남기고 모델 입력으로 승인하지 않는다.

공식 주관사 쪽은 `official_underwriter_source_readiness.parquet`로 먼저 통제한다. 이 파일에는 주관사별 일반 IPO 표본 수, 공개 탐색 경로, 문서 형식, 기관 경쟁률·확약의 공개 제공 여부, 표본 감사 근거와 다음 행동을 저장한다. [한국투자증권 공모주 공지 목록](https://securities.koreainvestment.com/main/research/corporate/ipo/Pre01.jsp)은 공개 목록과 확정발행가·청약 안내는 확인되지만, 이번 표본에서는 기관 통합 경쟁률·확약이 검증되지 않았다. 따라서 해당 값의 상태는 `not_verified_from_public_sample`이고, URL 자동 추측·로그인 자동화·전수 크롤링은 허용하지 않는다. 다른 주관사도 같은 표본 검증을 통과하기 전에는 `not_verified`로 유지한다.

**실행 순서:** (1) 키가 설정된 환경에서 DART v4 유통가능물량 및 최종 발행조건 통합 수요예측 파서 v1을 한 번 재수집하고, (2) 각 승인 행의 DART URL·접수일·근거 문구와 충족률을 감사하며, (3) DART 원문이 없는 사례만 우선순위 대표주관사의 공개 통합 결과 문서로 표본 검증하고, (4) 검증된 보조 원천만 별도 수집기로 확대한다. 이 네 단계를 완료하기 전에는 기관 경쟁률·확약 회수율, 모델 학습 가능 행 수, 모델 성능을 주장하지 않는다.

### 3.4 2026년 누락

현재 파일에는 2026 행이 없다. `--end-year 2026`을 실행했더라도 이를 증명하는 실행 매니페스트·요청/응답 로그가 없고, 상장 캘린더가 2025에서 끝난다. 코드상 원인은 다음 후보를 분리해 재현해야 한다.

1. KRX 기준일 요청이 2026-08-27에 실패하거나 빈 응답이었다.
2. 이전 실패 뒤 캐시가 저장되었다.
3. 최신 실행이 중단되어 산출물이 완성되지 않았다.
4. “연도 마지막 기준일” 방식 자체가 미래 날짜에 부적절하다.

현 파일만으로 단일 원인을 단정할 수는 없다. 다음 실행부터는 요청 기준일, API 상태, 응답 행 수, 캐시 재사용 수, 코드 커밋을 실행 매니페스트로 남겨야 한다.

## 4. DART 014·공시 계보 감사

### 4.1 확인된 사실

`dart_document_failures.parquet`에는 `rcept_no`, 회사명, 접수일, 이유, 기록시각만 저장되어 있고, 275건 모두 `014_file_not_found`다.

| 접수 연도 | 014 건수 |
|---:|---:|
| 2015 | 47 |
| 2016 | 46 |
| 2017 | 47 |
| 2018 | 62 |
| 2019 | 54 |
| 2020 | 12 |
| 2021 | 2 |
| 2022 | 0 |
| 2023 | 1 |
| 2024 | 3 |
| 2025 | 1 |
| 합계 | 275 |

2015~2019년이 256건으로 93.1%다. 이 집중은 “과거 기업에 IPO 공시가 없다”는 증거가 아니라, 오래된 원문 ZIP 보존 상태·잘못 선택된 접수번호·계보 탐색 부족을 먼저 검증해야 한다는 신호다.

현재 실패 파일에는 `report_nm`, `corp_code`, 후보 접수번호 목록, 선택 이유, DART 목록/구조화 API 상태가 없어 원인별 건수를 산출할 수 없다. 요청한 층화 표본 교차검증도 이 메타데이터 없이는 재현 불가능하다. 실제 API 호출도 이번 감사에서는 하지 않았다.

OpenDART 원문 API는 접수번호 하나에 대한 ZIP 원문을 반환하는 API이며, 014는 **그 접수번호의 원문 파일이 없음**을 뜻할 뿐 회사 전체의 공시 부재를 뜻하지 않는다. 지분증권 구조화 API는 법인 고유번호와 기간을 사용해 별도 조회할 수 있다. [공시서류 원본 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003), [지분증권 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS006&apiId=2020054)

### 4.2 코드상 원인과 고착 위험

현재는 KRX 회사명 정규화와 DART 회사명 정규화이 일치하는 후보 중 상장일 이전 400일의 가장 늦은 접수번호 하나를 선택한다. `corp_code`는 선택 이후에야 사용한다. 접수번호가 실패 목록에 있으면 이후 실행에서 원문 호출을 하지 않는다.

즉, 잘못 고른 “마지막 정정본”이 014이면 최초 신고서·다른 정정본·발행조건확정본을 탐색하지 못한 채 영구 실패처럼 고정될 수 있다. 이는 중대 오류다.

각 이벤트에 후보를 모두 보존하고, 다음 중 하나의 상태를 기록해야 한다.

| 상태 | 판정 방법 |
|---|---|
| 관련 공시 없음 | KRX 공식 모집단 이벤트에 대해 corp_code 기반 DART 목록·발행공시 검색 모두 없음 |
| 접수번호 선택 오류 | 같은 corp_code/공시 계보의 다른 후보가 존재하며 선택본만 014 또는 날짜·증권종류 불일치 |
| 웹 원문 존재·ZIP 부재 | 웹 공시 화면 존재, `document.xml`만 014; 수집 시각·응답 상태 보존 |
| 구조화 API 값 존재·원문 실패 | `estkRs`의 동일/연결 계보 값이 있음 |
| 원문 존재·파서 미추출 | ZIP 원문 해시 저장 후 추출 필드가 결측 |
| 엔터티 매칭 오류 | corp_code, ISIN/ticker, 상장일, 증권종류 중 하나가 불일치 |

계보 선택은 `KRX 이벤트 식별자 → ISIN/티커 → DART corp_code → 후보 접수번호 목록 → 정정/철회/발행조건확정 관계 → 실제 상장일·증권종류` 순으로 해야 한다. 회사명은 후보 검색 보조키일 뿐 최종키가 되어서는 안 된다.

## 6. 확정 공모가 규칙 감사

현재 코드의 최신 규칙은 예전 140자 주변 탐색보다 개선됐다. 확정가 라벨과 `원`/`KRW` 금액이 같은 문장 또는 같은 HTML 표 행에 있는 경우만 자동 승인하며, 단위 없는 금액은 검토 큐로 보낸다.

그러나 다음 이유로 출시 승인 규칙에는 아직 부족하다.

1. 같은 표 행에 “확정 공모가·액면가·희망밴드·총공모금액”이 공존할 수 있어 셀 구조·헤더 연결까지 검증하지 않는다.
2. 라벨과 금액 사이에 최대 28문자를 허용하며, 문장 분리와 HTML 정규화가 표의 열 의미를 잃을 수 있다.
3. `[발행조건확정]` 계보를 하나만 선택하고, 정정·철회·투자설명서의 최신성 전체를 검증하지 않는다.
4. 구조화 `slprc` 대조는 같은 접수번호만 허용하므로, 구조화 API의 최초접수일 기반 계보와 최신 정정본 연결을 별도로 기록하지 않는다.
5. 수동 오버라이드 파일은 접수번호·공모가·결정만 필수라 원문 근거 URL, 검토자, 검토 시각, 사유를 강제하지 않는다.

출시용 자동 승인 조건은 다음 모두를 만족해야 한다.

`최종 조건 문구 + 한 주당 통화단위 금액의 동일 문장/동일 표 행·헤더 + 유효한 최신 계보 + 구조화 API/주관사 공지 중 하나의 독립 대조 + 희망밴드·액면가·총액과의 의미 구분`

어느 하나라도 불일치하거나 원문을 못 읽으면 삭제하지 않고 `review_required`로 격리한다. 수동 승인은 원문 URL/접수번호, 값·통화·단위, 검토자, 시각, 사유, 재검토 상태를 남긴다.

## 7. 시간 기준·백테스트 감사

### 적합한 부분

- 타깃 공식은 요구사항과 일치한다. 시초가·종가 수익률은 공모가 대비 각각 별도로 계산한다.
- 시장 모멘텀은 상장일 이전 지수만 사용한다.
- backtester는 시간순 확장 윈도우이고, 각 윈도우에서 결측 중앙값을 학습 구간으로 계산한다.

### 중대 위험

| 위험 | 현재 상태 | 영향 |
|---|---|---|
| 미래 정보 누수 | `per_vs_sector_median`이 전체 데이터 중앙값 | 과거 검증 행이 미래 IPO PER을 봄 |
| 같은 날 타깃 누수 | 최근 IPO 평균은 동일 상장일의 앞 행을 과거로 취급 가능 | 상장 후 수익률이 동시 상장 종목 피처에 섞일 수 있음 |
| 잘못된 섹터 | 코스닥 소속부를 산업 섹터로 사용 | 섹터 온도/PER 의미 상실 |
| 재무 as-of 미검증 | 상장 전년 사업보고서만 연도 기준으로 조회 | 이른 상장 기업에는 당시 아직 공시되지 않은 연간 보고서 사용 가능 |
| 최종 학습 결측 처리 | 전체 학습에서 `.fillna(0)` | 결측을 실제 0으로 왜곡 |
| 표본 혼합 | 분류 필터 없음 | 스팩·이전상장 등이 같은 모델에 섞임 |
| 신뢰구간 과장 위험 | 표본이 작고 구성도 편향 | 배포용 위험 등급/상승확률의 통계적 근거 없음 |

현 코드의 46개 타깃은 2020년 5, 2021년 7, 2023년 3, 2024년 16, 2025년 15건에만 있다. 2015~2019 및 2022년은 0건이다. 이 중 잠정 스팩이 26건이라, 최소 3년 훈련·5건 검증이라는 walk-forward 조건을 만족해도 일반 IPO의 일반화 성능을 평가할 수 없다.

그러나 이는 공식 원천이 아니라 민간 서비스의 편집·집계 정보다. 사이트는 게시판 정보·의견에 대한 책임을 게시자/열람자에게 두고, 증권정보·분석자료·시세는 단순 정보 제공 목적이라고 고지한다. [38커뮤니케이션 이용 안내 하단 고지](https://www.38.co.kr/html/forum/com_list/form.htm)

| 위험 | 서버 저장만으로 해결되는가 | 처리 원칙 |
|---|---|---|

## 9. 승인 전 개선 우선순위

### P0: 학습 차단 및 기준 데이터 확정

1. KRX 신규상장종목 현황/KIND 기준으로 2015~현재 공식 이벤트 마스터를 만들고, 증권구분·주식종류·상장유형·폐지일을 저장한다.
2. 일반 IPO/스팩/이전/재상장/리츠/외국기업/종류주/비대상을 공식 코드와 근거로 분류한다.
3. 이벤트 마스터·실행 매니페스트·산출물 버전·소스 커밋을 함께 저장한다.
4. 분류 완료 전 `train`과 `backtest`를 일반 IPO 모델에 대해 차단한다.

### P1: DART 계보와 공모가 신뢰성

1. corp_code 중심 후보 계보 테이블을 만들고, 014를 접수번호별 재검증 가능한 상태로 바꾼다.
2. 014 실패를 영구 캐시하지 말고 TTL·코드 버전·후보 변경을 기준으로 재시도한다.
3. 원문/구조화/주관사 공지의 독립 대조, 수동 감사 로그를 추가한다.
4. 2015~2019, 2020~2022, 2023~현재 각 구간의 계층 표본을 별도 감사해 원인별 정확도를 측정한다.

### P2: 피처의 as-of 보장

1. 모든 값에 `available_at`, 출처, 파서 버전, 결측 사유를 추가한다.
2. 결측을 0/0.5로 바꾸는 로직을 제거하고, 학습 폴드 내부 대체 + 결측 플래그로 전환한다.
3. KRX 업종명 또는 공인 산업분류로 산업 피처를 교체한다.
4. 롤링 통계는 날짜 단위로 엄격히 과거만 사용하고, 동일 상장일 이벤트는 전부 제외한다.
5. 재무제표는 실제 공시 접수시각이 예측시점 이전인 경우에만 사용한다.

### P3: 그 다음에만 모델 평가

1. 일반 IPO만의 충분한 연도별 표본을 확보한 뒤, 고정된 시간 홀드아웃으로 시초가·종가를 별도 평가한다.

## 결론

이번 문제는 정규식 한 개의 결함이 아니라 **표 구조 손실, 추출과 승인 결합, 불충분한 감사 근거, 캐시 고착, 학습 게이트 누락**이 연결된 시스템 문제다. DART는 여전히 유효한 공식 원천이지만, 문서 안에 수치가 존재한다는 사실과 그 수치가 해당 IPO의 통합 기관 경쟁률·통합 의무보유확약이라는 사실은 별도로 검증해야 한다.

## 원인 사슬

1. DART 원문의 표는 회사·연도별로 병합 셀과 다단 헤더가 다르다.
2. 기존 `_TableRowParser`는 빈 셀과 셀 병합 정보를 제거했다.
3. 열 의미를 잃은 뒤 첫 번째 또는 마지막 비율이라는 휴리스틱으로 값을 골랐다.
4. 파서의 비결측 반환값에 파이프라인이 곧바로 `verified` 상태를 붙였다.
5. 캐시는 값과 잘린 문자열만 보존해 선택 셀을 사후 재현하기 어려웠다.
6. 단계 데이터셋은 검증 상태가 아닌 비결측 여부만 완전성으로 계산했다.

코넥스 제외 정책을 적용했다. [KIND 신규상장기업현황](https://kind.krx.co.kr/listinvstg/listingcompany.do?method=searchListingTypeMain)의 실제 시장 선택값 1(유가증권)·2(코스닥)을 사용해 별도 조회한다. 공식 화면은 신규상장 당시 자료임을 명시한다. 기존 시장 NULL 캐시는 보존 후 범위 버전 1로 교체한다. 코넥스·시장 불명 행의 가격 조회와 학습 후보 편입도 차단한다.

실제 조회한 2015~2026-09-10 결과는 1,288건(코스피 189·코스닥 1,099), 시장 누락 0건이다. 저장된 기존 1,514건과 이벤트 ID로 비교해 제외 226건·추가 0건을 확인했다. 연도별 건수는 2015=128, 2016=88, 2017=99, 2018=109, 2019=112, 2020=100, 2021=127, 2022=121, 2023=133, 2024=127, 2025=104, 2026=40이다. 이 숫자는 일반 IPO 모수가 아니라 두 시장의 공식 상장 이벤트 수다.

로그에 제시된 2022~2023년 8개 이벤트는 모두 제외됐다. 지에프씨생명과학의 2025-06-30 코스닥 이전상장 행은 독립 이벤트로 보존됐다. 이전상장 공모 여부와 모델 적격성은 별도 기존 검증을 따른다. 이번에는 가격·DART 재수집이나 모델 학습을 실행하지 않았으며, DNS 장애 및 다른 원인의 가격 미매칭까지 해결 완료라고 판단하지 않는다.

코넥스/시장 불명 가격 호출 차단, 동일 종목의 코스닥 이벤트 유지, 공식 조회 시장 파라미터, 학습 후보 차단을 회귀 검사에 포함했다.

전체 테스트 113개를 통과했다. 기존 Pydantic 폐기 예정 경고 2개는 이번 시장 범위 수정과 별개다.

### 2026-09-10 KRX 중단 로그 추가 감사

사용자 로그는 `sto/ksq_bydd_trd`, `20230126` 요청의 타임아웃 후 DNS 해석 실패로 중단됐다. 이것은 응답 2,552~2,559행 안에서 이벤트 코드·회사명이 발견되지 않은 앞선 경고와 별개다. 로그만으로 서버 장애인지 사용자 네트워크 장애인지까지 확정할 수 없다.

로컬 이벤트 마스터에서 `102950`, `390110`, `448780`, `446600`, `388610`(2022년), `447690`, `346010`, `052960`의 시장이 모두 NULL임을 확인했다. [KIND 게시 애니메디솔루션 보고서](https://kind.krx.co.kr/external/dst/corpReport/64788120250717104438.pdf)는 2022년 12월 코넥스 상장을, [KIND 게시 태양3C 보고서](https://kind.krx.co.kr/external/dst/corpReport/64834120260602085428.pdf)는 2023년 1월 코넥스 상장을 명시한다. 이 두 건은 코스피·코스닥만 조회하는 현재 범위에서 빠지는 사례다. 자료는 KIND에 게시된 기업 보고서이며 해당 날짜 일별 가격 응답을 직접 검증한 것은 아니다. 나머지 6건도 같은 원인이라고 확정하지 않는다.

중단 복구 결함은 수정했다. `_collect_listing_prices`가 25행마다, 그리고 요청 오류 발생 시 완료한 행을 기존 가격 캐시와 병합해 원자적으로 저장한다. 실패 행은 저장하지 않으며 재실행에서 다시 요청한다. 오류 주입 회귀 검사와 전체 111개 테스트를 통과했다. DNS 복구·시장 재정합·전체 가격 미매칭 해결까지 완료했다는 뜻은 아니다. 모델 학습 보류는 유지한다.

### 범위와 결론

`0ab11bc` 이후 공개 DART 원문을 실제로 내려받아 2015·2020·2023·2025년 네 기업을 대조했다. 선택 기준은 과거 오류 사례, 오래된 표 형식, 다단 합계 헤더, 정정 전후 혼재, 전액 신주/구주 구조다. 민간 사이트는 사용하지 않았다.

**이 표본들에는 기관 경쟁률과 통합 확약이 DART에 존재했다.** 따라서 과거의 0%를 DART 원천 부재로 해석하는 것은 잘못이다. 파서뿐 아니라 표지·정정 요약만 내려받은 표본 수집 경로에도 문제가 있었다. 이번 검증은 공개 HTML에 한정하며, 전체 IPO 모집단이나 실제 API ZIP 전송·계보 연결까지 검증한 것은 아니다.

### 구현 및 검사

파서 v6은 표 밖 제목, 단위가 헤더에만 있는 경쟁률, 신청수량 기준 직접 확약 비율, 검산 가능한 전체 확약 수량, 희망 밴드 통화 단위, 명시적 전액 신주/구주, 공모 후 유통가능 열을 지원한다. 예정·개인청약·배정 후 수량·주주 보호예수와 혼동하는 반례도 검사한다. 구버전 값은 전체 재처리 전까지 신규 검증값으로 승격하지 않는다.

`scripts/official_sample_expectations.json`은 원문에서 대조한 값과 URL·SHA-256을 고정한다. 실제 파서 출력에서 기대값을 자동 갱신하지 않는다. `scripts/audit_official_samples.py --cached-only`로 네 기업의 7개 접수번호, 8개 문서·절, 56개 필드를 모두 재검사했다. 기대 결측과 정정 충돌도 통과 건수에 포함되므로 이를 56개 신규 학습값 또는 전체 정확률 100%라고 표현하면 안 된다.

원문·파싱 근거는 무시 대상인 로컬 `data/raw/official_sample_audit/`에 보존한다. 저장소에는 코드·회귀 테스트·공개 출처와 해시·기대값만 포함한다. API 키·인증 헤더·쿠키는 사용하거나 기록하지 않았다. 대용량 응답 중단은 `.part`로 격리하며, 실제 완료한 공식 절별 문서만 감사에 사용했다.

전체 자동 테스트 110개, 컴파일 검사 및 `git diff --check`를 통과했다. Pydantic v1 문법에 대한 기존 폐기 예정 경고 2개는 남아 있다. 테스트 통과는 전체 데이터나 모델 성능의 승인이 아니다.

### 전체 기간 확대 전 남은 조건

1. 현재 실행 셸에 DART/KRX 키가 없다. 저장된 전체 ZIP 원문 캐시도 없어 2015~현재를 오프라인으로 v6 재파싱할 수 없다. 따라서 이번에는 전체 `collect`를 실행하지 않았다.
2. 인증된 실행 환경에서 같은 표본 접수번호의 실제 ZIP/XML 경로를 먼저 대조해야 한다. 공개 HTML 검증은 `document.xml` 014 해결의 증거가 아니다. ZIP이 없는 경우에는 웹 원문과 계보 대체 경로의 출처·시점 보존을 별도로 검증한다.
3. 실제 IPO 연결·최종 정정 선택·공모가 일치·예측 시점 이전 공개를 통과하는지 통합검사한 뒤 기간을 확대한다. 2016~2019·2021~2022·2024·2026, 혼합 신주/구주 등 이번 표본에 없는 층도 추가해야 한다.
4. 이후 연도별 원천 상태, 충족률, 거절 사유, 일반 IPO 학습 가능 행 수를 다시 산출한다. 현재 생산 데이터의 충족률이나 학습 가능 행이 개선됐다고 주장하지 않는다.

**현재 판정: 공개 HTML 회귀 표본 통과, 전체 수집·통합 검증 미완료, 실제 모델 학습·성능평가 계속 보류.** 전체 확대 및 모델 승인은 이 스크립트의 표본 통과만으로 자동 부여되지 않는다. API 제공 범위·이용 조건·서비스 표시 권한, 표본 편향, 과거 정정 시점, 최대주주 보호예수 및 위험요소 피처의 별도 품질 검증도 남아 있다.
